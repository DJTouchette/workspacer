#small on purpose

The first work{spacer} was an Electron app: a bundled browser, a Node runtime, and helper processes to keep alive. The native app is one Rust binary that draws its own window. The hub and the session engine are compiled into it.

native package 34 MB
electron appimage 169 MB
download size on linux x64, with the hub and the session engine in both · the native binary unpacks to 107 MB
one_binary

Nothing to keep alive

The window owns the hub, the MCP tools and the session engine in one process. There is no daemon to install, no Node, and no helper to keep in step with the app. Quit, and everything it started is shut down with it.

no_webview

It draws its own pixels

The interface is rendered straight to the GPU by GPUI. There is no Chromium, no DOM and no webview compiled in. Long lists are virtualized, so only the rows on screen are built.

bounded

It knows when to stop

An open conversation keeps at most 2,000 rows and 4 MiB of text in memory. Screen updates are capped near 30 a second while an agent streams, and network and JSON work stay off the UI thread.

No memory or CPU numbers here, on purpose. The only ones we have were taken on a software renderer, and those aren't the ones you'd see. The download sizes are real.

#one skill: spawn-agent

Every agent work{spacer} starts carries it. With it, an agent can start a child on any supported CLI, give it one self-contained task, and end its turn. The child's progress, blockers and result come back as messages. Nothing is written into your repo.

01 ask

Say it in the prompt

“Have Codex review this.” The agent honours the provider or model you name. Name nothing and your configured default applies.

02 spawn

A real session

The child is a full agent on its own CLI, not a subagent that returns a paragraph and vanishes. It nests under its parent, and you can open it, steer it, or approve for it.

03 isolate

A worktree when it edits

Code changes go to a fresh git worktree on its own branch, so parent and child never write over each other. Read-only work stays in the current checkout.

04 wake

No polling

The parent stops after spawning. It is woken when the child finishes, gets stuck, or reports progress, and it checks the result before calling the work done.

#a list and a conversation

That's the app. There are no panes to tile, no layouts to save and no dashboard to learn. The sidebar sorts itself by who needs you, and everything else opens over the chat without touching your draft.

needs_you

Answer where it's asked

Approvals and questions sit in the conversation they belong to. Allow once, deny with a note, or pick from the options the agent offered. Type while it works and your message steers it.

new_agent

Starting one is a message

New Agent is a conversation that hasn't started yet. Pick the folder, type the task, choose Claude or Codex, press Start. Leave the task empty and the agent starts idle.

changes

Review and ship

The diff the agent left, with the changed files beside it. Stage, commit and push, or publish a worktree branch, without dropping to a shell.

#and from the couch

The app carries its own hub, so the same sessions are reachable from your phone, a terminal, or another agent. Sharing is off until you turn it on.

remote

Pair a phone in Settings

  • Over your own tailnet. Settings → Remote serves the hub over Tailscale HTTPS to devices signed in to your tailnet. Nothing is published to the internet.
  • One QR code per access level: read-only, triage (approve, answer, chat, interrupt), or full control.
  • Revoke a link and that phone is disconnected immediately.
same_hub

Or skip the window

  • Every agent gets the tools. Agents work{spacer} starts receive its MCP tools automatically: list sessions, read transcripts, spawn, message, answer. That is how one agent calls another.
  • Any MCP client can drive it. The same tools are there for anything else that speaks MCP, with tokens you can scope to view, triage, or operate.
  • Headless. workspacer-rust serve runs the same backend with no window, for a box that has no desktop. Point the app at it with --bus.
  • Or a terminal. wks-tui is a Rust client on the same bus, with a ctrl-k palette and vim keys.
#what this is, and what it isn't

work{spacer} is alpha and built in the open by one person. Here is the list you'd otherwise find out the hard way.

Alpha, and it means it. Sharp edges, breaking changes between releases, and features that land faster than the docs describing them.
The Electron app is on its way out. This release ships it alongside the native app; the next release deprecates it. New work goes into the native app, and the Electron app keeps its own docs.
Native does less, on purpose. The Electron app's tiled panes, embedded browser, plugin panes, brief board and Fleet Manager are not here. The Fleet Manager is not coming to the native app either: here, agents hand work to each other with the spawn-agent skill. If you depend on one of the others, use the Electron app for now.
The builds are unsigned. Windows warns you and lets you click through. The app tells you when a newer release exists: on Windows it can install it and restart, on Linux you unpack the new archive yourself.
There is no native macOS package. A signed, notarized bundle isn't set up, so on a Mac you build the native app from source or use the Electron app. The download section has both.
Quitting stops your agents. The window owns them. Close-to-background is a setting, or run the hub headless and attach to it. A stopped Claude or Codex session can be resumed from History.
Bring your own CLIs and subscriptions. work{spacer} drives Claude Code, Codex, OpenCode and GitHub Copilot. It doesn't replace them, resell them, or proxy them.
The providers aren't at parity. You start Claude Code or Codex from the app. OpenCode and Copilot only arrive as spawned children, and Claude Code is where the deepest integration lives.
Worktrees isolate branches, not environments. Agents share your machine, dependencies, ports and network. If you need a sandbox, this isn't one.
It's for one person on their own machine. No accounts, no multi-user model. The tokens are capabilities, not logins.
It doesn't read your code. No indexing, no code intelligence, no answers about your repo. That's a different kind of tool, and work{spacer} is happy to run agents that use one.
MIT, and the whole thing is here. The native app, the hub, the session engine, the TUI and this page. Fork it, gut it, ship your own.

windowsThe release build attaches an installer, Workspacer-Native-Rust-Preview-Setup. It is unsigned, so SmartScreen warns and lets you through.
linuxThe release build attaches an archive, workspacer-native-…-linux-x64.tar.gz. Unpack it and run ./install.sh: it installs for your user, and wks-native-uninstall removes exactly what it wrote. make package-native-linux builds the same archive from source.
macosNo native package yet. Build it from source with Xcode's command-line tools and Rust (make run-native-local), or use the Electron app's Apple Silicon .dmg. That one is unsigned too: after dragging it to Applications, run xattr -dr com.apple.quarantine /Applications/Workspacer.app.
