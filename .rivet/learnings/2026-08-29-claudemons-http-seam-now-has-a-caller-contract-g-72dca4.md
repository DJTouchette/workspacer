# claudemon's HTTP seam now has a caller contract; GET /usage/report has never had a caller

## Observation
Two findings from building the claudemon route contract (2026-08-29).

(1) The repo ALREADY derived claudemon's route table before this work: `services/hub/internal/capspec/httproutes.go` classifies all 37 routes and `httproutes_test.go` scans `.route()` calls out of `api.rs`/`hook.rs` (Rust) from a Go test, with `claudemonRouteFloor = 36`. What was missing was the CALLER half. The new guard therefore lives in the same package (`claudemoncallers_test.go`) rather than inventing a mechanism, and the shared table is `contracts/claudemon-routes.json`, GENERATED by `make claudemon-routes` (which runs `UPDATE_CLAUDEMON_ROUTES=1 cargo test --lib routes_contract` in services/claudemon).

(2) `GET /usage/report` — the widest read on claudemon's loopback plane (every provider, every configured login, spend, quota headroom, per-model breakdown) — has NEVER been called by anything in this repo. `git log -S "usage/report" -- apps/desktop services/hub` returns only the capspec classification commit and the release-notes commit. The 0.160.0 changelog (`renderer/src/lib/changelog.generated.ts:35`) states it powers the Overview cost tile, the Inspector's Usage tab and the History pane. It powers none of them. This is the mirror image of the dead-/git-caller bug: a served, documented route with no caller.

Also: claudemon's HTTP callers are far more numerous than "apps/tui + the desktop". The full enumeration is 25 files across three languages, and includes several that are easy to miss — claudemon's OWN `watch` TUI (`src/tui/app.rs`), the four provider adapters that hand an agent a `{api_base}/mcp/ask/{session_id}` callback URL, the `claudemon wrap` default `ws://127.0.0.1:7891/wrapper` (composed with `/{session_id}` in `wrapper/mod.rs`), and `daemon/init.rs`, whose curl command lines make CLAUDE CODE ITSELF a caller of the hook router.</observation>
<parameter name="impact">A renamed or deleted claudemon route used to produce nothing but a 404 nobody read: apps/tui's `mock_server` answered the configured status for ANY path, so ~20 route assertions pinned the caller's own URL against itself and could not fail. That is how six dead `/git` calls survived six weeks with a green suite. The new sweep names every orphaned caller across Rust/TS/Go; verified by deleting `/sessions/:id/handoff` from api.rs, which produced three named failures (apps/tui, claudemonSessionClient.ts, cmd/brain/claudemon.go).

## Recommendation
Before adding or deleting a claudemon route, run `make claudemon-routes` and then `go test ./internal/capspec/` in services/hub — the second one tells you which callers you just broke. New claudemon client? Add a row to `claudemonCallers`; the repo-wide discovery test fails until you do. For `/usage/report`: either wire the three UI surfaces the changelog names, or delete the route and correct the note.
