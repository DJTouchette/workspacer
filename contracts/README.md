# Cross-language contracts

Golden fixtures that pin behaviour reimplemented in more than one language, so the
copies cannot silently drift. Each file is loaded by a test in **every** language
that owns a copy of the logic; the test asserts identical output for identical
input. If you change one implementation, the fixture forces you to change (or
consciously extend) the others.

| `model-context-windows.json` | `services/claudemon/.../session/windows.rs` (Rust) · `apps/desktop/.../main/shared/modelContextWindows.ts` (TS) · `services/hub/cmd/brain/windows.go` (Go) | The CONTEXT WINDOW, table and resolver. There were **five** hand-maintained window tables in this repo and three of them disagreed for the same model id: a `gpt-5-codex` session reported 272000 through the provider status line and 200000 through `usage`, at the same instant, for the same session, depending on which client asked. `windows` is the table itself and is pinned IN ORDER — first match wins, which is what makes `fable` beat the generic `claude` row, and `kind` is normative (`o3`/`o4` are PREFIX rows so an `o3` buried in an unrelated id does not match, which is the one case a substring port fails). `markerCases` pins the narrower "was 1M asked for" question: Claude Code strips `[1m]` from the id it writes into the transcript, so the spawn request is the only carrier of that choice, and an unmarked alias must answer **null** — "says nothing", not "200k". `resolutionCases` is the block that actually pins the twins, because it exercises the RESOLVER rather than the table: provider-reported > user `~/.workspacer/model-rates.json` override > requested-model marker > table > unknown, plus the drift alarm. Two arms are deliberate reversals of what shipped before — an explicit `context_limit` override now outranks the `[1m]` marker (it was a `max()`, so a coarse alias could silently overrule what the user wrote), and a peak beyond the claimed window no longer PROMOTES it to 1M but disarms it to unknown and logs. `expected: null` is a first-class answer throughout: unknown is spelled null and omitted on the wire, never the 200000 that four sites used to spell it — including `emptyUsage()`, which asserted a 200k window before a single token had been counted. |

| `agent-error-marker-cases.json` | `services/claudemon/.../providers/mod.rs` (Rust, the WRITER) · `apps/desktop/.../main/shared/workerFailure.ts` (TS, the READER) | How a provider-side failure is spelled in a conversation. | `dispatch-template-params-cases.json` | `apps/desktop/.../main/lib/dispatchTemplate.ts` (TS) · `services/hub/cmd/brain/dispatchparams.go` (Go) | The placeholders a Fleet Manager dispatch template declares, as `library.list` advertises them: `{name, required, default?}`, in first-seen order. Both providers answer `library.list` — the desktop's under a local client, the brain's under the default catalog delegation (every web/mobile/MCP caller) — so a manager must not learn a different param set depending on which one ran. `required` is the load-bearing field: a bare `{{task}}` REFUSES the spawn when unfilled and only the author's explicit `{{task:default}}` may be omitted, so advertising it wrong is worse than not advertising it at all. The drift this pins is whitespace: the TS copy spells its token with JavaScript's `\s` and trims with `String.prototype.trim()`, and neither of Go's obvious equivalents is that set — `regexp`'s `\s` is only `[\t\n\f\r ]` (no vertical tab, no NBSP) while `strings.TrimSpace`/`unicode.IsSpace` adds U+0085 that JS does not trim and omits U+FEFF that JS does. A template padded with any of those would parse to a param name the caller cannot fill, on one provider only, which is why `dispatchparams.go` writes the class out by hand. The Go copy PARSES but never renders: `agents.spawn`'s `template` stays declined headless (`parity_test.go` `spawnParamsDeclined`). |
| `brief-board-cases.json` | `apps/desktop/.../shared/briefBoard.ts` + `services/briefBoardService.ts` + `services/briefCheck.ts` (TS) · `services/hub/cmd/brain/briefboard.go` + `briefcheck.go` (Go) | A project brief read as ENTRIES: what one is, what an archive move does to the two files, and which `## Now` lines have outlived their dispatch. `brief.append` was ported to the headless brain first and `brief.archive`/`brief.check` were deliberately declined, because both read the brief as a bullet plus its continuation lines under a `##` or a `###`, and a subtly wrong port of that boundary does not fail loudly — it drops the wrong lines out of a user's document, or flags live entries and misses dead ones. That reasoning expired when the node started running the MCP facade: a HEADLESS Fleet Manager became a real caller and lost two of the three brief tools its doctrine names to `no provider` at the bus level. So the model is ported, and the original objection is answered HERE. Three blocks. `entries` pins the boundary rules (a blank line closes an entry, four leading spaces do not, a `#` with no space after it is not a heading, a `###` entry belongs to its parent `##`) and the byte-exact round trip. `archive` pins the move end to end — both files' bytes, in a real temp dir through each provider's real implementation — including WHICH END is the oldest (`## Recently` is newest-first, so a copy that took its first entries would archive exactly what the manager was keeping) and the append-only batch heading. `check` pins the report, session rows included, so the liveness predicate is pinned too: a stopped, ended or archived row is GONE, which is the whole point (a worker that finished cleanly is precisely the case that leaves a Now line behind). The whitespace case is the one that catches a lazy port: JavaScript's `\s` includes U+00A0 and Go's regexp `\s` does not, so a heading padded with one is a heading on one provider and prose on the other — which moves every boundary below it. The findings' `detail` prose is deliberately not pinned here; `cmd/brain/briefboard_test.go`'s `TestBriefCheckWordingMatchesTheDesktop` holds it against `briefCheck.ts` directly. |

Rates are USD per **million** tokens. Add a case whenever a new model id or merge
edge case ships; the cheapest place to catch drift is here, before it becomes a
mispriced session or a clobbered config.
