# MCP migration evidence

The Go MCP source remains an independent behavior reference while the Rust
facade supplies actual transport, authentication, schemas and composition.
See `reviews/mcp.json` for already recorded slices and the additional review
plan generated by the remaining-facade audit. A catalog match proves schema
coverage, not tool execution parity.

`assets/mcp-tools.json` and `assets/mcp-help.json` preserve the original Go
capture as reviewed source contracts. Rust-specific descriptions live in
`assets/mcp-rust-presentation.json`; explicit typed-input omission rules live
in `assets/mcp-wire-contract.json`. Deliberate current Rust semantics are documented
separately in `assets/mcp-wire-overrides.json`. The portable project command is:

```sh
python3 scripts/mcp-catalog.py --write
python3 scripts/mcp-catalog.py --check
python3 -B -m unittest discover -s scripts -p 'test_mcp_catalog.py' -v
```

It generates `mcp-effective-tools.json`, `mcp-effective-help.json`, `mcp-effective-wire.json` and an input
provenance manifest. Runtime code consumes the generated assets. Generation
checks schema/wire agreement, pointer omission safety, tier and help closure,
duplicate/missing tools, description-only overrides and deterministic output.
Tests prove it works when the legacy Go tree is absent. The independent Rust
overlay test additionally compares generated presentation and preserves every
non-description schema value. The optional stdlib-only Go wire oracle is in
`tools/go-mcp-wire-reference`; it is not required by normal builds or generation.
Status-summary guidance still requires its actual desktop provider.

Go schema optionality alone does not identify `omitempty` semantics. Reviewed
rules project each built-in tool independently: value zero/false/empty fields
are omitted only when their original tag says so, while nonnil pointer values
survive. Nested freeform maps and plugin parameters pass through unchanged.
This preserves, for example, `notify_when` with `contextUsedPct:80,tokens:0`,
without erasing `skipPermissions:false`, `option:0`, `text:""` or a forecast of0.

The old Go MCP `*uint64` context field collapsed explicit null to omission; its
fresh-Codex default then requested1M. The shared Rust spawn planner already
preserves field presence: explicit null requests the provider default. Authored
per-method context overrides therefore retain null for spawn, retry, live-model
selection and an explicit workflow model. MCP default resolution now honors
that distinction too. Tests pin omitted versus null fresh-Codex requests,
canonical modelIdentity plus null, retry inheritance and composed dispatch.
Nonnullable scalar null is rejected by schema validation before projection or
provider calls; this is deliberately not a claim about raw Go encoding/json
behavior without the SDK validation layer.

The remaining-facade audit adds actual HTTP/broker regressions in
`tests/mcp/parity.rs`, transport-specific preference checks in
`tests/mcp/sse_preferences.rs`, and independent config guards in
`mcp/config_save.rs`. The old data-loss guard was two layers: advertised object
schemas plus a local wholesale-map check independent of the MCP SDK. Both are
now retained. Empty task-reference coordinates are refused before provider
calls. Legacy JSON-string spawn IDs support first-message delivery, and a bare
model override omits an unavailable canonical context window.

Existing Rust behavior deliberately improves uncertain-delivery handling:
`messageQueued:false` is an unconfirmed receipt, not permission to send the
prompt again. Spawn errors retain the receipt and prohibit blind replay.
Task-reference CAS conflicts remain ordinary domain data rather than transport
failures. Modern discovery/list cache hints remain `ttlMs:0` and private.

## Former standalone facade entry point

The separate Go MCP process is retired; the shared Rust facade is owned by
`workspacer-rust serve` or the embedding application's `Options`. Runtime
transport/authentication is covered separately from merely listing tool names.

| Former MCP option/responsibility | Rust owner and contract |
| --- | --- |
| `-addr` | `serve --mcp-port` keeps the default loopback listener; embedders use `Options.mcp_listen` for an explicit socket. The old component-only process is not recreated. |
| `-hub`, outbound `-token` | Local serve connects in process. Upstream worker mode uses `--upstream` and a separate scoped facade-authority caller credential; it refuses borrowing owner/provider credentials. |
| `-mcp-token` / `WKS_MCP_TOKEN` | `serve --mcp-token` wins over the environment. A separate static facade credential remains operator-only, not host administration. |
| `-tokens` | Global `--tokens-file`; the default remains under the selected config directory. Mint/revoke is rechecked on requests. |
| `-untokened` / `WKS_MCP_UNTOKENED` | Same deny/view/operator vocabulary and precedence. A configured static credential disables credential-less access regardless of the dial. Live host configuration is supported. |
| HTTP/SSE and health | Same `/mcp`, legacy `/sse` and health identity; actual listener and upstream readiness are reported. Host/Origin pins and modern private cache hints are exercised through the real transports. |
| SIGINT/SIGTERM, parent death, shutdown | The launcher owns joined backend/facade cleanup, parent PID and pipe-EOF cancellation. Existing standalone signal/parent tests and the isolated MCP CLI test prove listeners are released. |

`tests/mcp/cli.rs` starts the actual owned control-plane/MCP launcher twice
(flag and environment paths), checks health plus owner/static/scoped/revoked
credentials, and closes the parent pipe while the parent still lives. It uses
isolated state and an environment allowlist; no daemon, model or cloud action
is started. Old binary override flags remain explicit errors instead of a Go
fallback.
