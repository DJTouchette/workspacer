# Persisted-state upgrade evidence

Read-only audit, 2026-09-30. Source checkpoint inspected: `43ba19af00748418daaa91395aa5cdf07e3b915f` plus the coordinated working tree. This document does **not** verify the `persisted-state-upgrade` gate. No tests or builds were run for this documentation task. Named assertions below were read; execution receipts are separate, scoped checkpoints. The ledger's source hashes establish what was reviewed, not that every store was executed together on the current revision.

Separate per-family fixture/restart/failure proofs can satisfy the gate. A universal all-store fixture and downgrade support are **not** additional requirements imposed by this audit. Remaining gaps concern particular loader/failure or execution evidence, not the absence of one giant test.

## Paths and identity come before parsing

`src/cli/serve.rs` and `src/services/state_paths.rs` preserve the historical `workspacer-hub` directory when the selected configuration directory is the standard one. macOS uses `~/Library/Application Support/workspacer-hub`; the other platform branch uses the standard configuration directory's sibling. Explicit data/config overrides and native Rust Preview isolation are deliberate separate state selections. Selecting an empty new directory is not proof that old state upgrades.

The real CLI child fixture in `tests/cli.rs` seeds historical layout, jobs, usage pacing and VAPID bytes, starts the Rust executable with isolated HOME/USERPROFILE/config roots, reads the retained public state and checks that the historical VAPID key did not rotate. It also distinguishes explicitly selected custom configuration state. `host_identity_first_run_empty_directories_state_loss_and_concurrent_creation` checks create-once identity, empty precreated directories, missing identity amid existing config, explicit identity reset and six concurrent creators agreeing on one token. `explicit_worker_identity_migration_preserves_existing_key_and_never_prints_it` checks the deployment migration opt-in.

Review owners: [launcher review](reviews/launcher.json), [main bootstrap review](reviews/cmd-hub-main.json), [migration architecture](MIGRATION.md). A packaged upgrade receipt must retain these path/identity assertions; merely finding `remote-token` somewhere is insufficient.

These families must not disappear merely because the initial gate description names the larger stores.

- **Analytics and pricing:** `headless-analytics.sqlite` and `model-rates.json`. `tests/analytics.rs::persistent_headless_analytics_retains_deduplicated_model_splits_and_filters` reopens real SQLite after deleting a transcript and preserves totals; corrupt DB is an error, not measured empty history. These dependency tests were read here, not executed by compiling the hub; attach the claudemon test-job receipt separately. Previous exit metadata must not be mistaken for current liveness.
- **Intentionally ephemeral state:** broker subscriptions, live peer sockets, terminal leases, threshold watches, progress throttles and live sidebar projections are not serialized as durable successes. Persistence of session/task IDs must not imply these connections or one-shot effects survived a restart.

## Concrete gaps and the next evidence decision

1. **Pin receipts to the final integrated revision/platform.** Source reviews and local logs below are useful evidence, not final CI for every dirty correction. This is a receipt gap, not a request to duplicate all tests. The manager owns this gate and the CI decision.
2. **Preserve the family-specific recovery evidence.** Profiles already have an actual malformed-file public-list/add refusal with unchanged bytes. Plugin settings intentionally retain the Go empty-overlay fallback. Neither is a newly missing migration behavior. OS-level unreadable-profile testing was not identified, but that is narrower than malformed-file coverage and is not automatically an extra cutover requirement.
3. **Resolve provenance and execution receipts without inventing schemas.** Current-schema task/manager/review reopen tests strongly cover durable semantics. Explicitly identify which supported old companion documents are represented in those fixtures if cross-version import is claimed; this bounded audit did not establish every historical version. Claudemon already has old-schema/failure/reopen tests, so the remaining need there is the owning-crate execution receipt, not a new hub migration implementation. No new test has been requested here.
4. **Keep explicit data-loss outcomes visible.** Host identity loss refuses by default; lost push key resets unusable subscriptions; layout persist failure keeps live state while warning; corrupt config protects old bytes; malformed jobs retain last good schedule. A generic “all corruption fails closed and preserves every byte” statement would be false.

No product defect is asserted solely because a receipt is missing. No universal transactional migration across unrelated stores, arbitrary power-failure guarantee, or downgrade contract is inferred.
